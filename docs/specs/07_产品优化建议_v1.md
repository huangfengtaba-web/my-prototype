# GTX FSO Litho · 产品优化建议 v1（面向客户核心排程问题）

> 日期：2026-10-25（同日：Opt2/3/4/5 前端演示已实施——①算法开关加「下游 Hungry」权重与预测窗口；②Reticle Transport 加搬送耗时动态校准卡（P50/P95→采纳写回 Transport Config）；③Scanner 页加 QTime 前瞻风险队列条（LOTHIST Over 概率）；④Run Trace 加 What-if 试算对比（同 SNAP 异 CFG 的 KPI diff，试算 Run 不入生产版本序列）） ｜ 视角：解决客户核心排程痛点（QTime Risk / 光罩不可用等待 / 温层切换浪费 / 负载不均与 TrainSize / BARC 控货 / 急货插单 / 求解可用性）。
> 标注：✅=本轮/此前已闭环；🆕=本轮已实施；📌=建议排期（按收益/成本排序）。

## 1. 求解可用性：超时降级与求解性能 🆕📌
- **痛点**：MILP 超时（日志案例 e03：600s 超时 gap 12.4%）导致排程不可用或结果差；客户产线 24h 运行，排程窗口有限。
- **已实施**：config_zone 新增「算法开关」页签（需求 38 体系化）：约束/组批 8 项开关、目标权重（TrainSize/负载/QTime 违反 Σ=100）、**超时降级策略（FIFO/EDD/CR + timeLimit + chunk≤50 可配）**；开关变更记入 CFG_VER 可 Run Trace 回放。
- **建议排期**：chunk 并行求解 + warm start（上轮解热启动）；降级解标记"降级原因"供运维跟踪。
- **验收指标**：单轮求解 P95 ≤ 5min；超时时降级解 makespan 与最优解 gap ≤ 15%。

## 2. Hungry / Next Loop Hungry 打分配置化 🆕
- **痛点**：RFP 2.1.4 的 Next Loop Hungry 目前只有界面呈现，打分口径硬编码（缺口 🟡）；不同产品/客户权重不同。
- **方案**：把「下游 Hungry 程度」打分公式参数化进算法开关（扩展现有权重区：Hungry 权重 + 预测窗口天数）；打分明细进决策审计表 reason_code（基础设施已备）。
- **验收**：Hungry 权重调整 → Barc Schedule 放货顺序可观测变化，且 Run Trace 可解释。

## 3. Reticle 搬送仿真精度：从静态耗时到动态校准 🆕
- **痛点**：搬送耗时用 Transport Config 静态矩阵；实际 AMHS 有波动（急货案例 +4min 即体现）。搬送估计偏乐观 → 到机时光罩未就绪 → 机台等料。
- **方案**：FSO_PLAN_ACTUAL 已回流实绩——把**搬送耗时偏差**纳入校准建议（自动统计 P50/P95 分位，更新 Transport Config 建议值，人工审批生效）；SDR 回执 actualTime 直接回写。
- **验收**：光罩就绪时刻偏差 |dev| ≤ 3min（P90）；机台因罩等待时长周环比下降。

## 4. QTime 风险预测：从硬卡控到前瞻预警 🆕
- **痛点**：QTime 目前是排程内硬约束（防 Over），但"即将 Over"的队列风险要等人看甘特才发现。
- **方案**：基于 LOTHIST 历史停留分布，对每个 QTime Loop 计算"预计 Over 概率"，在 Scanner/Barc 页面顶部加风险队列条（数据基础：宽表携带 LOTHIST 后即可做——见 06_会议清单 A6）。
- **验收**：Over QTime 发生前 ≥2h 预警命中率 ≥80%。

## 5. What-if / Plan B 对比 🆕（前端演示已实施，求解器接入后即生产可用）
- **痛点**：PE 调参（权重/开关/时间窗）靠经验，改完只能等下轮结果；不敢在生产参数上试。
- **方案**：重放基础设施已具备（SNAP+CFG+ALGO 版本链天然支持同输入重算）——补一个"试算对比"入口：选两次 Run 并排甘特/KPI diff（makespan、QTime 违反、切换次数、TrainSize）。
- **验收**：两次 Run 的 KPI 对比一键生成；试算 Run 不污染生产结果版本序列。

## 6. 温层优化：从切换代价到温度轨迹 📌（阶段二）
- **痛点**：当前按 capability_temperature_change 矩阵算固定切换代价；实际转温时间与起始温度相关（每度耗时已配置但仅近似）。
- **方案**：细排程温层约束改为温度轨迹插值；甘特图转温段可视化（紫色条），让"为什么这个 Lot 排晚 20min"在界面可解释。
- **依赖**：机台温度遥测数据（EAP），建议纳入宽表二期。
